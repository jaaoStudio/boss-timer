# 部署切換後停掉舊 slot，不做跨容器廣播

WebSocket 的房間訂閱只存在單一後端容器的記憶體中。Blue/green 部署切換流量後，若舊 slot 繼續存活，部署前建立的連線會留在舊容器上（nginx WebSocket 逾時長達 24 小時），同一房間的成員被拆成兩群、彼此收不到即時更新。我們選擇在切換流量後停掉舊 slot，讓前端自動重連到新 slot 並重新取得完整房間狀態，代價是回滾需要重新啟動舊 slot（約 1 分鐘），不再是瞬間切換。

## Considered Options

- **Redis pub/sub 跨容器廣播**：兩個 slot 共享廣播，不需斷線，回滾維持瞬間切換。但需重寫 ConnectionManager（含跨容器在線人數），且新舊版本會同時服務同一房間，訊息格式一改就會發生版本不相容。單機部署下，這些成本只換到「回滾快 1 分鐘」，不划算。
