# 限流採「個人額度 + 真實 IP ×50 天花板」雙層

只用 IP 限流時，學校、網咖等共用 IP 的玩家會共用額度、瞬間用完（後端當時讀到的甚至可能是 Cloudflare 節點 IP，全台玩家集中在少數節點上）；改用 `anonymous_user_id` cookie 後雖然公平，但 cookie 由客戶端決定，每次請求換一個就能完全繞過限流。我們改成兩層並存：**個人額度**依登入身分或 cookie 計算，維持公平；**IP 天花板**依 `CF-Connecting-IP` 取得的真實 IP 計算，設為個人額度的 50 倍（假設單一 IP 後最多 50 位真實玩家），只用來擋換 cookie 繞過與資源灌爆。長時間窗（每天）才是擋「不眠不休灌資料」的關鍵，因為真人用量是短暫爆發、長期累計很低（2026-10 實測：每人每分鐘回報 P99 為 3、每天最多 365 筆；全站每小時建房最多 15 間）。

## Considered Options

- **天花板放在 traefik**：traefik 看不到 WebSocket 連線內的訊息，回報 Boss 的 IP 天花板仍得在程式內做，規則會分散兩處。traefik 只負責 cf-only（只接受 Cloudflare 來的連線），這是 `CF-Connecting-IP` 可信的前提。
- **計數器存 Redis**：可跨部署與 blue/green slot 保留計數，但每次部署歸零是可接受的代價，不值得多一層依賴。

## Consequences

- cf-only 以 Cloudflare IP 白名單實作，網段不保證永久不變，需每日比對 `/ips` 的 etag 自動同步並寄信通知；若同步壞掉，新網段的使用者會被擋。
- 計數器存在記憶體，每次部署歸零，「每天」上限實際上是「每次部署週期」上限。
